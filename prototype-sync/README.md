# Изолированный прототип офлайн-хранилища

Этот каталог — экспериментальный стенд. Он не подключён к рабочему `index.html`, Service Worker, GitHub API, Supabase или настоящему серверу.

## Безопасность и ограничения

- Используется отдельная IndexedDB: `checklist_sync_prototype_v1`.
- Текущие ключи `localStorage` и база фотографий приложения не читаются и не изменяются.
- ID сотрудника в прототипе — только локальная метка для проверки выборок, а не способ аутентификации или защиты от подмены.
- Кнопка имитационной синхронизации никуда не отправляет данные.
- Не вводите настоящие персональные данные и не подключайте прототип к рабочим токенам.
- Не переносите эти файлы в корень сайта и не объединяйте с рабочим интерфейсом без отдельного аудита.

## Локальный запуск

Нужен Python 3. В корне репозитория выполните:

```sh
python -m http.server 8000
```

Откройте:

- Стенд: http://localhost:8000/prototype-sync/
- Тесты: http://localhost:8000/prototype-sync/tests.html

Для проверки офлайн-режима сначала откройте стенд, затем отключите сеть и попробуйте сохранить/прочитать запись. IndexedDB работает локально в браузере, но сама HTML-страница должна быть загружена; Service Worker и офлайн-кэш в этот прототип пока не добавлены.

## Тесты

Страница `tests.html` проверяет пустой ID сотрудника, локальное сохранение, очередь, фильтрацию по ownerId, успешную имитацию отправки, сохранение конфликтной операции и запрет синхронизации без транспорта.

Тесты используют уникальный ID на каждый запуск и не очищают всю базу прототипа автоматически. При необходимости удалить все экспериментальные данные используйте кнопку очистки на стенде — она действует только на `checklist_sync_prototype_v1`.

## Что ещё не реализовано

- Настоящая аутентификация и серверная авторизация.
- Защита данных на сервере через политики доступа.
- Получение изменений с сервера и разрешение конфликтов.
- Повторные попытки, backoff и надёжная обработка одновременных сохранений/синхронизаций.
- Миграция данных из существующего приложения.
- Автоматические тесты в настоящем браузере/CI.

Перед производственным использованием требуется отдельная реализация и аудит. Клиентская фильтрация по ownerId сама по себе не обеспечивает приватность между сотрудниками.
