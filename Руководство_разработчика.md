# Руководство разработчика: конструктор оборудования

## 1. Вход
1. Откройте приложение и на экране входа введите логин `developer` и пароль разработчика (выдан отдельно).
2. После входа в левом нижнем углу появляется кнопка **🛠 Разработчик**.
3. Сменить пароль: `python3 tools/make_dev_hash.py "новый_пароль" приложение/index.html`, затем поднимите `CACHE_VERSION` в `sw.js` и опубликуйте файлы.

> Вход разработчика проверяется в браузере и **не является защитой**: его можно обойти. Настоящая защита публикации — токен GitHub (см. п. 3). Без токена изменить файл на сайте нельзя.

## 2. Как создать оборудование
В окне конструктора слева — список оборудования, справа — редактор.

- **Название** — как оно будет в списке выбора и в чек-листе.
- **Формат размещения:**
  - *на каких секциях* — все, только кабины (1–2) или только бустерные (3 и выше);
  - *сколько таких узлов в секции* (например, 2 → «№1», «№2») **или** названия узлов построчно (например, «Левый», «Правый»).
- **Поля** (операции). Два вида: «Выпадающий список» и «Текстовое поле».
  - *Наименование операции* — подпись поля.
  - *Варианты ответов* — по одному в строке. Отметьте **нормальные ответы**: для них фото не требуется.
  - *Фотография:* «нужна, если ответ не из нормальных» / «нужна всегда» / «не нужна». Для текстовых полей: «не нужна» / «по желанию» / «нужна всегда».
  - *Несоответствия:* ответ вне нормальных считается несоответствием (попадает в итог «Наличие выявленных несоответствий»).
  - *Подсказка* и *пояснение к ответам* (красным) — тексты под операцией.
- Кнопки ↑ ↓ меняют порядок полей и оборудования.

Ограничения: не более 30 полей на узел (больше в Excel не помещается); символы `<` и `>` в названиях удаляются.

## 3. Токен GitHub (один раз)
1. GitHub → *Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token*.
2. *Repository access:* **Only select repositories** → выберите `prilogenia`.
3. *Permissions → Repository permissions → Contents:* **Read and write**. Остальное не нужно.
4. Срок действия — разумный (например, 90 дней).
5. В конструкторе: **⚙ GitHub** → вставьте токен → *Проверить доступ* → *Сохранить*. Флажок «запомнить» сохраняет токен только на этом устройстве; без него токен живёт до закрытия вкладки.

Токен даёт доступ ко всему репозиторию `prilogenia` (GitHub не умеет ограничивать токен папкой). Храните его только на доверенных устройствах.

## 4. Предпросмотр и публикация
- **👁 Предпросмотр** открывает настоящий комплексный чек-лист с вашим оборудованием (серия 2ЭС5К, № 591). Данные предпросмотра хранятся отдельно и рабочие чек-листы не затрагивают.
- **🚀 Опубликовать** записывает файл `oborudovanie.json` в репозиторий (коммит в ветку `main`). GitHub Pages обновится через 1–3 минуты; пользователи увидят оборудование при следующем открытии комплексного чек-листа.
- **⬇ Экспорт / ⬆ Импорт** — резервная копия и перенос файла вручную.
- Черновик автоматически сохраняется на вашем устройстве.

## 5. Откат
Каждая публикация — отдельный коммит. Чтобы вернуть прежнюю версию: на GitHub откройте файл `oborudovanie.json` → *History* → нужный коммит → *Revert* (или скопируйте старое содержимое), либо импортируйте старый файл в конструктор и опубликуйте.

## 6. Важно знать
- **Не меняйте число и названия узлов (блоков) и порядок полей у оборудования, по которому уже заполняются чек-листы**: данные привязаны к позиции узла, при изменении они могут оказаться не на своих местах.
- Сайт GitHub Pages доступен всем, у кого есть ссылка (для бесплатных репозиториев): всё опубликованное, включая `oborudovanie.json` и `zona_riska.xlsx`, видно любому.
- Конструктор пока создаёт оборудование **только для комплексного чек-листа** (зависимые поля и новые чек-листы целиком — следующие этапы). Особые блоки вроде КПС конструктором не воспроизводятся.
- Узлами из конструктора можно управлять правилами на листе «Узлы» файла `zona_riska.xlsx` — по названию оборудования.
