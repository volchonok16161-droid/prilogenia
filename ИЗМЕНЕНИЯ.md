# Что изменено (сборка cache v12)

**Фото и 100%**
- ТТ/БИ: «Найти незаполненное» не требует фото у полей без блока фото (ложные 8 позиций).
- Гидродемпферы: `updateStats` считает через `computeStats` (учёт обязательных фото), экспорт больше не открывается при недостающих фото; подсветка кнопки фото гаснет после прикрепления.
- Комплексный: правило «не требуется / отсутствует ШУ» единое для процента, поиска и подсветки.
- Процент считается `Math.floor` (99,5%+ больше не показывается как 100%).

**Данные**
- `saveState` ловит переполнение localStorage; фото уходят в IndexedDB и восстанавливаются; нет ложного «Сохранено».
- ТТ/БИ: «Место осмотра» больше не стирается при «Продолжить» и при уходе фокуса с поля номера.

**Прочее**
- Пароль администратора — хеш SHA-256 с солью (это не защита: роль admin читается из localStorage).
- `tools/check_consistency.py` переписан под текущий формат; константы `EMBED_*_B64` → `EMBED_*_HTML`.
- `sw.js` v11, отдельные maskable-иконки, текст инструкции про темы.

**Новое: справочник локомотивов в Excel (`zona_riska.xlsx`) + кнопка «📍 Зона риска»**
- Список локомотивов, приписок и мест осмотра вынесен в отдельный файл `zona_riska.xlsx` рядом с `index.html`. Листы: ТТ, БИ, Гидродемпферы, Комплексный, КМБ (у каждого свой список) и общий «Места осмотра». Файл уже заполнен текущими данными.
- **Чек-листы берут список из этого файла**: перед запуском чек-листа приложение читает файл и подставляет данные в «Общие данные» (тип → номер → приписка → место осмотра). Новый локомотив = новая строка, удалённый = удалённая строка. Изменения подхватываются при следующем открытии чек-листа.
- Если «Место осмотра» указано у конкретного локомотива — в чек-листе предлагается только оно; если пусто — все места его приписки.
- Встроенный список остаётся в `index.html` как запасной: он используется, только если файл не удалось прочитать (нет связи и файл ни разу не загружался).
- Ошибки в файле (неизвестная серия, нет приписки, повтор, приписка без мест) не ломают чек-лист: такие строки пропускаются, а окно «Зона риска» перечисляет их с номерами строк.
- Кнопка «📍 Зона риска» в верхней панели каждого чек-листа: фильтр по приписке, поиск по номеру/серии/месту, для открытого локомотива — его приписка и место осмотра.
- Файл подтягивается «сначала из сети», без сети — последняя сохранённая копия (`sw.js`).
- Чтобы обновить список: замените `zona_riska.xlsx` на сервере (имя не менять, первую строку и названия листов оставить).

**Новое: какие узлы осматривать — правила в Excel (лист «Узлы»)**
- Для отдельных номеров, диапазонов номеров, серий или приписок можно оставить для осмотра только нужные узлы («Только») или исключить лишние («Кроме»).
- Узлы: секции (все чек-листы), оборудование (комплексный, КМБ), типы гидродемпферов и тележки (гидродемпферы). Точные названия — на листе «Список узлов».
- Правила применяются сразу после выбора номера локомотива; скрытые узлы пропадают из выбора, из подсчёта процентов и из выгрузки.
- Если подходит несколько строк, действуют все: сначала объединяются «Только», затем вычитаются «Кроме». Правила работают отдельно для каждого вида узлов (например, «Только Секция №1» не скрывает оборудование).
- Узел с опечаткой или строка без узлов не ломают работу: окно «Зона риска» показывает такие ошибки списком.
- Меняйте правила до начала заполнения: если изменить их для локомотива, чек-лист которого уже заполняется, введённые данные могут оказаться привязаны не к тем узлам (это не проверялось).

**Новое: роль «разработчик» и конструктор оборудования (этап 1)**
- Вход: логин `developer` (пароль хранится хешем; смена — `tools/make_dev_hash.py`). После входа появляется кнопка «🛠 Разработчик».
- Конструктор создаёт оборудование для комплексного чек-листа без правки кода: название, поля (выпадающие списки и текстовые), варианты ответов, «нормальные» ответы, правила фото (при отклонении / всегда / не нужно), подсказки, формат размещения (секции, количество или названия узлов).
- Предпросмотр на настоящем движке чек-листа (в отдельном хранилище, рабочие данные не затрагиваются).
- Публикация кнопкой: файл `oborudovanie.json` записывается в репозиторий GitHub через API (нужен токен; настройки владелец/репозиторий/ветка/файл — в «⚙ GitHub»). Экспорт и импорт файла, черновик на устройстве.
- Оборудование из конструктора работает во всём чек-листе: проценты, фото, «Найти незаполненное», сохранение, выгрузка в Excel (проверено на имитации ExcelJS), правила узлов (лист «Узлы» по названию оборудования).
- Ограничения этапа 1: только комплексный чек-лист; нет зависимых полей и создания чек-листов целиком; не более 30 полей на узел (предел выгрузки Excel).
- Подробности — `Руководство_разработчика.md`.
