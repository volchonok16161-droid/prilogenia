# Документооборот чек-листа: план внедрения

## Принципы
- Чек-лист является источником условий уведомлений; наличие замечания, необходимость уведомления, отметка передачи, формирование файла и наличие оформленной копии — разные факты.
- Первый тип документа — `housings_notice`, уведомление по кожухам. Текст и формат не утверждены, ждём образец. Для других узлов есть универсальный идентификатор шаблона, но автоматическое формирование не включено.
- Группировка нескольких операций в один документ (на осмотр / секцию / операцию) будет определена по образцу; текущая модель хранит по одному *основанию* на сработавшую операцию.
- Акт осмотра формируется отдельно; подготовка файла, подпись, загрузка скана и проверка подписи разделены.
- Только подтверждённая облачная загрузка может изменить состояние копии на «загружена». Отметка работника не заменяет проверку хранения или подписи.

## Внедрённая основа
- `prototype/checklist-document-register.js`: версия структуры 1, реестр шаблонов, основания уведомлений и машинные строки для аналитики.
- `prototype/checklist-runtime.js`: передаёт основания активных уведомлений в процесс облачного сохранения.
- `prototype/supabase-cloud-backup.js`: записывает `payload.documents` вместе со снимком чек-листа без фото и без дублирующих временных полей.
- `prototype/checklist-document-export.js`: при создании Excel добавляет лист «Реестр документов» с одной строкой на основание уведомления и строкой акта; прежние листы сохранены.
- `prototype/checklist-details.html`: в раскрываемых дополнительных сведениях показывает наличие оснований по кожухам.

## Следующая итерация после получения образцов
1. Согласовать точный шаблон уведомления, реквизиты, обязательные поля, группировку оснований и порядок нумерации.
2. Добавить версионируемые шаблоны, проверяемый генератор и предварительный просмотр документа.
3. Реализовать частное облачное хранилище копий уведомлений с owner-scoped доступом, журналом событий, проверкой MIME/размера, откатом при ошибке записи.
4. Реализовать генерацию акта по утверждённому образцу и загрузку подписанной копии.
5. Расширить данные реестра фактическими ссылками на подтверждённые записи, а не только отметками внутри состояния.
6. Добавить блокировку окончательного закрытия осмотра при обязательных отсутствующих документах; промежуточное сохранение и работа с черновиком остаются возможными.
7. Подготовить согласованные столбцы Excel для BI (ID осмотра, ID документа, тип, версия, статус, метки времени, подтверждение копии), не включая персональные подписанные файлы в книгу.

## Совместимость
Существующие облачные копии без `payload.documents` читаются как устаревшие; отсутствие записи не равно отсутствию необходимости в уведомлении. Новое сохранение создаёт `payload.documents`; старые данные не переписываются автоматически.
