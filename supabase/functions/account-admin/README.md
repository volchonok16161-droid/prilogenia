# Управление аккаунтами сотрудников

Edge Function: `account-admin`.

## Статус
Код добавлен в ветку `development/account-system`. Он ещё не развёрнут в Supabase и не подключён к интерфейсу приложения. Не считать его работающим до тестов.

## Доступные действия
Все запросы — POST с заголовком `Authorization: Bearer <access_token>` и JSON:
- `{"action":"list_employees"}` — список сотрудников.
- `{"action":"invite_employee","email":"...","display_name":"..."}` — приглашение сотрудника по email.
- `{"action":"set_employee_access","user_id":"<uuid>","suspended":true}` — заблокировать вход.
- `{"action":"set_employee_access","user_id":"<uuid>","suspended":false}` — восстановить вход.

## Защита
- Функция проверяет JWT через Supabase Auth и роль вызывающего пользователя по серверной таблице `profiles`.
- Только роли `developer` и `admin` могут выполнять операции.
- Service role используется только внутри Edge Function.
- Сотруднику можно менять доступ только к аккаунту с ролью `employee`.
- Профили не должны быть доступны для записи из браузера.

## Перед развёртыванием
1. Убедиться, что проект — тестовый Supabase, а не production.
2. Проверить, нет ли триггера на `auth.users`, который уже создаёт строки `profiles`. Если есть, согласовать вставку профиля, чтобы не получить дублирование.
3. Проверить настройки SMTP/приглашений Supabase Auth.
4. Применить `supabase/account_admin_permissions.sql` в SQL Editor тестового проекта (добавляет service_role права SELECT/INSERT/UPDATE на profiles; не выдаёт их authenticated).
5. Развернуть функцию через Supabase CLI из каталога проекта.
6. Протестировать вызовы под developer, admin и employee; employee должен получать 403.
7. Проверить приглашение, письмо, создание профиля, блокировку и восстановление тестового сотрудника.
8. Проверить параллельные приглашения: текущая проверка лимита 15 выполняется до создания пользователя и сама по себе не является атомарным ограничением при одновременных запросах. До production нужно перенести лимит в транзакционную серверную процедуру/блокировку.

## Важное
Функция пока не подключена к HTML. Нельзя помещать `SUPABASE_SERVICE_ROLE_KEY` в браузер, HTML, репозиторий или сообщения. Никогда не отправляйте пароли/ключи в чат.
